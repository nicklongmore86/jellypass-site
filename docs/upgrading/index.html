Upgrading and rollback

Upgrade

  1. Read the release notes in the changelog for every version between yours and the new one, and the notes below. Each says whether the state file or any setting changes.
  2. Back up the data folder (see Backup and restore).
  3. Set JELLYPASS_IMAGE in .env to the new version, then: 
    docker compose pull
docker compose up -d
curl http://127.0.0.1:8788/health

Each release is published as X.Y.Z, plus X.Y and X tags that move to the newest release in that line. latest follows the main branch and may contain unreleased changes. Restarting JellyPass signs administrators out of the admin site.

Version notes

Upgrading to 4.2.0

No setting changes, and the state file stays at schema 9. The setup wizard now asks you to review an existing Seerr webhook before replacing it. Scripts that call POST /v1/setup/webhook with replace: true must first read GET /v1/setup and send the reviewed expectedState, expectedCurrentUrl and expectedTargetUrl; without them they get 400 review_required. See the 4.2.0 notes.

Upgrading to 4.1.0

No setting has to change, but:

  • The state file moves to schema 9 on the first start, and 4.0.0 can't read it. JellyPass first writes a backup next to the file, grants.json.v8.bak (.v7.bak from a 3.x file), or a timestamped one whose path it logs if a different backup is already there.
  • TV_ADDON_HOUSEHOLDS is deprecated. While set, it works as in 4.0.0 and locks the new TV switches. To move to the switches, check they show what you want, remove the variable and restart.
  • The Compose file needs Docker Compose 2.24 or newer, because it marks .env as optional. With no configuration at all, JellyPass now starts its setup wizard instead of stopping.
  • The TV add-on's script has a new name. No CDN purge is needed.

See the 4.1.0 notes.

Upgrading from 3.x to 4.0.0

4.0.0 is a breaking release, so change your configuration in this order. Upgrade from 3.9.x or later 3.x; from 2.x, go through 3.9.x first. The full steps are in the changelog.

  1. Back up the state file, .env and the Compose file.
  2. On the running 3.x, change Seerr's webhook: set the Authorization: Bearer WEBHOOK_TOKEN header, remove any ?token= from the URL, and use the full template. Both old forms are refused from 4.0.0.
  3. On a Jellyfin other than 12.x or 10.11.x, confirm its exact version first, or household addresses answer 503 after the upgrade.
  4. In .env, set TRUSTED_PROXIES to the reverse proxy's address if it is empty, and add LEGACY_WEBHOOK_ON_MEMBER_PORT=true for the switch-over.
  5. In the Compose file, add ADMIN_HOST: 0.0.0.0 and ADMIN_PORT: 8788 under environment, publish 8788 on a private address only (for example 127.0.0.1:8788:8788), and change any health check to http://127.0.0.1:8788/health.
  6. Point any admin proxy host at 8788 instead of 8787, and keep it gated. Household names stay on 8787.
  7. Pull the new image and recreate the container. Check curl http://127.0.0.1:8788/health, the startup log's admin and member listeners, and a household address. The member port answers anything else with 421.
  8. In Seerr, change the webhook URL's port to 8788, save and press Test. Then remove LEGACY_WEBHOOK_ON_MEMBER_PORT and recreate the container once more.

Existing addresses such as https://jelly-grove.example.com keep working as long as HOUSEHOLD_DOMAIN is set. The state file moves to schema 8, which 3.x can't read. The add-to-library page is gone; members use Get this.

Roll back

Pin the previous image; once you have checked it, set the same version in .env so it sticks:

JELLYPASS_IMAGE=ghcr.io/nicklongmore86/jellypass:PREVIOUS_VERSION docker compose up -d

If you use the household app, check this first, and roll back only once it answers "clear": true; the changelog explains how to drain it:

curl -H "Authorization: Bearer $ADMIN_TOKEN" http://127.0.0.1:8788/v1/app/outstanding
  • 4.2.0 to 4.1.0: the image tag alone. 4.1.0 runs on the same state file.
  • 4.1.x or later to 4.0.0: 4.0.0 stops at startup with unsupported state schema version and leaves the file alone. Stop JellyPass and restore the latest backup the upgrade wrote (grants.json.v8.bak, or the timestamped path it logged), losing changes made since, or use the in-place downgrade. 4.0.0 reads settings only from the environment and ignores settings.json, so a wizard install needs its settings in .env, and TV_ADDON_HOUSEHOLDS set again if you removed it and use the add-on.
  • 4.x to 3.x: 3.x can't read schema 8 or later. Restore your backup, or follow Rollback to 3.x, and put the 3.x Compose file, .env, Seerr webhook URL and any admin proxy host back on 8787.
  • To 2.x: unsupported. Restore a backup made with the release you intend to run.

Backup and restore

The state file is the data JellyPass must keep. A wizard install also keeps its settings in settings.json and its admin token in admin-token: back them up too, and keep them secret, since they hold your Jellyfin, Seerr and TMDB keys and your tokens.

docker compose stop jellypass
cp -p data/grants.json data/grants.json.backup
# With the setup wizard:
cp -p data/settings.json data/settings.json.backup
cp -p data/admin-token data/admin-token.backup
docker compose start jellypass

Back up Jellyfin separately: JellyPass is not a backup of Jellyfin's users or policies. To restore, stop JellyPass, put the backups in place (owned by UID 1000), start it, then preview and apply a reconciliation in Grants.

Jellyfin versions

JellyPass supports the current Jellyfin release and the one before it: Jellyfin 12.x and 10.11.x, tested with 12.4.0 and 10.11.11. It reads Jellyfin's version at startup and every five minutes. Any other version (an older 10.x, a future 13.0, or any build whose version has a suffix, such as 12.5.0-rc1) is unconfirmed until an administrator confirms it. On an unconfirmed version:

  • household addresses answer 503 and pass nothing to Jellyfin, from 4.0.0 (3.x only warned);
  • JellyPass logs a warning once for each version, the admin site shows it with an Allow Jellyfin X button, and GET /v1/jellyfin/version reports "confirmation": "unconfirmed" and "enforcement": "refuse";
  • the admin site, webhooks, grants and reconciliation keep working;
  • an administrator confirms that exact version with Allow Jellyfin X, or with JELLYFIN_UNTESTED_VERSION_OK. Confirm a version only once you are satisfied JellyPass's household privacy checks hold on it, since they were written for the supported versions. A later upgrade to another untested version is refused again until you confirm it in turn.

While JellyPass can't read the version (Jellyfin unreachable, or its last read failed), household addresses also answer 503. It starts anyway, tries again every 30 seconds and on household requests, and the admin site shows that the version can't be read. GET /v1/jellyfin/version then reports "version": null and "confirmation": null, with the last error.

Check JellyPass's release notes before upgrading Jellyfin to a new major version.
