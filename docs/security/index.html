Security

Keep the admin site private

The admin site, the administrator API, /metrics and the Seerr webhook are on the admin listener, port 8788, published on 127.0.0.1 by default. Household addresses and the member listener never serve them: there, any host name that is no household's gets a fixed 421.

The admin listener has no gate of its own beyond the sign-in. Anyone who can reach it can try to sign in with a Jellyfin administrator's name and password, and the admin API answers anyone holding the admin token. JellyPass limits sign-in attempts, but:

  • keep it on this machine or your LAN, and never publish it on a public address or route a public hostname to it;
  • if you proxy it for HTTPS, give it a host of its own, not a household address or Seerr's, behind an identity-aware gate, a VPN or an IP allowlist (see Reaching the admin site);
  • keep Seerr's webhook on the private network, too.

Household addresses and one-tap sign-in

With one-tap sign-in, anyone who can reach that household's address can pick a visible passwordless member and act as them. Use it only where everyone who can reach the address may do that. See One-tap sign-in.

Hiding a profile is no protection for a passwordless account. A hidden member also accepts an empty password when someone types their name, so knowing or guessing a hidden member's name is enough to sign in as them. The mark only changes the profile picker: any member with no Jellyfin password can be signed in this way, marked or not, and only a Jellyfin password protects them.

Marking a member does not remove their password. Marking a member who has a real password breaks only one-tap: tapping their profile fails. They can still sign in by typing their password.

Otherwise, knowing an address is not authentication. Anyone who can reach an address sees that household's sign-in page, with its visible members' names, and must still sign in as a member who has a password. A token is accepted on a household's address only for that household's members; another household's token gets the same 401 as an unknown one.

Household privacy holds only if members can't reach Jellyfin or Seerr directly. The Dashboard's Run self-check looks for that, but a check from inside can't prove it: test from a member's network too, including LAN addresses and alternate names.

Tokens and keys

  • Use different long random values for WEBHOOK_TOKEN and ADMIN_TOKEN. If neither ADMIN_TOKEN nor a setup token exists, the webhook token also unlocks the admin API.
  • The setup token stays the admin token. On a wizard install without ADMIN_TOKEN, the token in data/admin-token is the bearer token for the admin API, /metrics and the wizard. To rotate it, stop JellyPass, delete admin-token and start it again: it writes a new token and the old one stops working. Or set ADMIN_TOKEN, which wins from the next start, then delete the file.
  • Keep Jellyfin, Seerr and TMDB keys out of Git, screenshots and support requests. JellyPass never logs passwords, Jellyfin tokens, the Jellyfin API key or webhook tokens.
  • Send the webhook token in the Authorization header. Query-token webhooks were removed in 4.0.0, because a token in a URL can appear in logs: ?token= is refused with 400.

The data folder

The state file, grants.json, holds grants, households, Jellyfin user IDs and a catalogue of media names. On a wizard install, settings.json holds your Jellyfin API key, Seerr and TMDB keys and the webhook token, and admin-token holds the admin token. JellyPass creates them readable by their owner only; keep backups just as private.

Behind the proxy

  • Serve household addresses over HTTPS only, and redirect plain HTTP at the proxy, before anything reaches JellyPass.
  • Don't publish either listener directly to untrusted networks. Only your reverse proxy should reach 8787: JellyPass chooses the household from Host and can't tell whether a request came through the proxy.
  • Set TRUSTED_PROXIES to your proxies only. It is required with the household gateway on.
  • Keep a separate way to reach Jellyfin as an administrator that doesn't go through a household address.

Administrator sessions

The admin site signs in with Jellyfin: the password goes to Jellyfin, the temporary Jellyfin session is closed at once, and JellyPass keeps its own session in memory for 12 hours. Every five minutes it checks the administrator is still an enabled Jellyfin administrator. Restarting JellyPass signs everyone out.

Reporting a vulnerability

Please report security problems privately through GitHub's private vulnerability reporting: Security → Report a vulnerability on the JellyPass repository. Don't open a public issue for an unpatched vulnerability. Fixes go to the latest release line and the main branch; pin a version and read release notes before upgrading.
