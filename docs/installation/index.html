Installation

JellyPass runs as one container, published on GitHub Container Registry as ghcr.io/nicklongmore86/jellypass. A first run starts a setup wizard, so there is nothing to write by hand.

Docker Compose quick start

  1. Make a folder and get the Compose file:

    mkdir jellypass && cd jellypass
curl -LO https://raw.githubusercontent.com/nicklongmore86/jellypass/main/compose.yaml

  2. Create the data folder. The container runs as user node (UID 1000), which must own it:

    mkdir -m 700 data
sudo chown 1000:1000 data

  3. Pin a release instead of latest, which is rebuilt from the main branch and may hold unreleased changes. Use the newest version on the releases page:

    echo 'JELLYPASS_IMAGE=ghcr.io/nicklongmore86/jellypass:4.2.0' > .env

  4. Start it and read the setup token:

    docker compose up -d
sudo cat data/admin-token

    You can also read it with docker compose exec jellypass cat /app/data/admin-token. The token is never logged.

  5. Check it is up:

    docker compose ps
curl http://127.0.0.1:8788/health

    /health answers {"status":"ok","setup":"required"} until setup has finished, then {"status":"ok"}. It shows the process is running; it does not check Jellyfin or Seerr.

The setup wizard

On the Docker host, open http://127.0.0.1:8788/admin/ and enter the setup token. From another machine, use an SSH tunnel, then the same address:

ssh -L 8788:127.0.0.1:8788 user@docker-host

The JellyPass container must be able to reach Jellyfin and Seerr by the addresses you give. If they are in other Compose projects, put JellyPass on their network with a compose.override.yaml next to compose.yaml, naming that network (here media), then run docker compose up -d again. Other containers on it reach JellyPass as jellypass:

services:
  jellypass:
    networks: [default, media]
networks:
  media: {external: true}

Each step checks what you give it and stores the result at once, so you can leave and come back:

  1. Jellyfin: its address and an administrator's name and password. JellyPass signs in once, creates an API key named JellyPass, checks it and signs out. The password is never stored.
  2. Seerr: its address and API key (Seerr's Settings → General). Finish Seerr's own setup first, or it refuses the key.
  3. Seerr webhook: JellyPass generates a webhook token and points Seerr's webhook at the address you give, for example http://jellypass:8788, then has Seerr send a test. Seerr has one webhook: if another one is set, on or off, the wizard shows it and replaces it only after you review and confirm.
  4. TMDB key for the household apps, checked with TMDB.
  5. Request backfill: the cutoff is your install date, so no request made before JellyPass was installed is imported.
  6. Household addresses (optional): the household gateway, the household app and TRUSTED_PROXIES, which is required with the gateway on. See Reverse proxy.

Finish checks the whole configuration and starts JellyPass with it, in place. Only the Jellyfin step is required to finish; to change anything later, choose Setup in the admin site's top bar.

Until you finish, JellyPass runs in setup mode: port 8788 serves only the wizard, /health and Seerr's test notification, and answers everything else 503 setup_required. Port 8787 is not listening.

The setup token stays the admin token. Unless you set ADMIN_TOKEN, it is the bearer token for the admin API and /metrics for as long as JellyPass runs. Keep data/admin-token private. To rotate it, see Tokens and keys.

After setup

  1. Open http://127.0.0.1:8788/admin/ again and sign in with an enabled Jellyfin administrator account. JellyPass checks the password with Jellyfin and keeps only its own session, in memory, for 12 hours.
  2. Run Sync library so the Library tab lists your titles. A sync does not make anything private.
  3. If you skipped the wizard's webhook step, connect Seerr's webhook by hand.
  4. Create your households and give each its address (Groups → Addresses), then put those addresses behind your reverse proxy.
  5. Turn off Quick Connect in Jellyfin's own settings. A new Jellyfin has it on; household addresses refuse it either way, but it stays open on Jellyfin's own address.
  6. Choose Run self-check on the Dashboard. It checks for direct access to Jellyfin, Quick Connect, the proxy's headers, public Seerr access, the Jellyfin version and the TMDB key.

Check the ports

The Compose file publishes both listeners on 127.0.0.1 only, which suits a reverse proxy on the same machine.

  • 8788, the admin listener: to reach it from your LAN, change its line under ports: to the host's private address. If that address were 192.0.2.10, the line would be 192.0.2.10:8788:8788. Never publish it on a public address.
  • 8787, the member listener: it starts only with the household gateway on. Then curl http://127.0.0.1:8787/ answers 421 {"error":"unknown_host"}, because 127.0.0.1 is not a household address. That is the correct answer: there is no admin site or health check here.

Configure with environment variables instead

Every setting can be set in .env. A variable set there always wins over the wizard, which shows it as locked. With JELLYFIN_URL, JELLYFIN_API_KEY and WEBHOOK_TOKEN all set, the wizard is never shown and JellyPass starts directly.

curl -Lo .env https://raw.githubusercontent.com/nicklongmore86/jellypass/main/.env.example

Edit .env: set JELLYPASS_IMAGE to a release, and replace every placeholder, at least JELLYFIN_URL, JELLYFIN_API_KEY, SEERR_URL, SEERR_API_KEY, WEBHOOK_TOKEN and ADMIN_TOKEN. See Settings reference. Make the two tokens different long random values:

openssl rand -hex 32
openssl rand -hex 32

Remove a placeholder you want the wizard to fill instead. Then run docker compose up -d and set up Seerr's webhook by hand.

Build from source

Clone the repository and run every command below inside it. The container runs as user 1000, so create the state directory first and give it to that user:

git clone https://github.com/nicklongmore86/jellypass.git
cd jellypass
mkdir -m 700 data
sudo chown 1000:1000 data
cp .env.example .env
# Edit .env, or empty it to use the setup wizard.
docker compose -f compose.example.yaml up --build -d

Without Docker: Node.js 22 or later, then, inside the clone, mkdir -m 700 data (owned by the user that runs JellyPass), corepack enable, pnpm install --frozen-lockfile, pnpm build and pnpm start, with any settings in the environment. The admin listener then defaults to 127.0.0.1:8788.
