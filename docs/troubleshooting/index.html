Troubleshooting and FAQ

Start with the logs and the health check. Health is on the admin listener only:

docker compose logs --tail=100 jellypass
curl http://127.0.0.1:8788/health

The container stops with EACCES: permission denied

The container runs as UID 1000 and can't write the data folder. Run sudo chown 1000:1000 data and start it again.

The container stops with a settings error

JellyPass checks its settings at startup and names the one that is wrong, for example SEERR_URL and SEERR_API_KEY must be configured together, or TRUSTED_PROXIES is required when the household gateway is on: set it to your reverse proxy's address. HOUSEHOLD_APP_ENABLED needs the household gateway, Seerr and TMDB_API_KEY. See the Settings reference.

Everything answers 503 setup_required

JellyPass is in setup mode: the required settings are missing, or the wizard has stored some but has not been finished. Port 8788 serves only the wizard, /health and Seerr's test notification, and port 8787 is not listening. Open http://127.0.0.1:8788/admin/ and finish the wizard.

The wizard says Seerr refused the API key

Copy the key again from Seerr's Settings → General, and check that Seerr's own first-run setup is finished: an unfinished Seerr refuses every key.

A new title is in Library but not in Grants

A title becomes private only when Seerr's webhook arrives, the backfill finds its request, or an administrator assigns it. Common causes: it was added outside Seerr, it replaced media Seerr already had, it arrived before the webhook was set up, the requester's Seerr account isn't linked to Jellyfin, or the webhook is off, filtered to the wrong event, unreachable or using the wrong token. Assign it from Library, and set up the backfill.

The webhook gets 401

The bearer header doesn't exactly match WEBHOOK_TOKEN. Check for copied whitespace.

The webhook gets 400

webhook_query_token_removed_use_authorization_header means the URL has ?token=: remove it and use the Authorization header. webhook_payload_removed_use_current_seerr_template means the payload is an older, shorter one: paste the full template in Seerr's form. Refused webhooks are not retried, so the backfill picks up what they missed.

The webhook reports missing Jellyfin IDs

Set SEERR_URL and SEERR_API_KEY, use the full template (empty Jellyfin IDs can then be looked up), and make sure the requester was imported from Jellyfin.

A household address answers 421 or 404

421 {"error":"unknown_host"} means the name reaching the member listener is no household's address. Check the household's addresses in Groups → Addresses against the exact hostname and port in the browser, and that the proxy passes the original Host unchanged. 404 household_not_found means a legacy HOUSEHOLD_DOMAIN address whose group doesn't exist. More causes are under Common failures.

A household address answers 503

Jellyfin runs a version JellyPass doesn't support, or JellyPass can't read Jellyfin's version. Household addresses refuse to serve until that exact version is confirmed or the version can be read. If the admin site shows Allow Jellyfin X, see Jellyfin versions. If it says the version can't be read, check that JellyPass can reach Jellyfin.

The apps say access is off (403 app_access_disabled)

That household's Mobile app access switch is off. See App and TV switches.

The admin site or the webhook is unreachable

They are on the admin listener, port 8788, not 8787, which answers them with 421. Open http://127.0.0.1:8788/admin/, point Seerr's webhook at http://jellypass:8788/webhooks/seerr, and move any container health check to port 8788. If you upgraded from 3.x, see Upgrading from 3.x.

The Library tab is empty or out of date

Check that JellyPass can reach Jellyfin and that the API key is an administrator's, then run Sync library. CATALOG_SYNC_INTERVAL_SECONDS=0 turns off automatic syncs.

Changes don't reach every user

In Grants, preview a reconciliation, check the changes and apply them. New Jellyfin users are covered at the next reconciliation.

FAQ

Does a sync make my whole library private?
No. The catalogue is only an inventory. Titles become private through a request or an administrator.
Can a member see what another household asked for?
No. The apps never show who asked for a title or which household has it, and a title another household holds looks the same as one nobody has.
Do I need the apps?
No. Members can keep requesting in Seerr and watching in any Jellyfin app on their household address. The apps add Get this, My requests and discovery.
Where do I get the phone app?
It isn't publicly available yet: it is by invitation for now. Every member can use the household web app today. See Phone, web and TV apps.
Does it support request quotas?
Not in the apps: a member with a Seerr request quota sees titles as "Can't request" and can still use Seerr.
Can I use more than 100 households?
Only with the household app off.
Where do I report a bug?
In GitHub issues. Report security problems privately (see Security).
