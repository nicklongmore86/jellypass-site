Reverse proxy

Household addresses must be served over HTTPS by a reverse proxy you control. JellyPass decides which household a request is for from its Host header alone, so the proxy's job is simple but strict. Each example below has working files in the repository's examples/proxy/, and uses grove.example.com and heath.example.com as two households' addresses. Replace them with your own, one per household; no wildcard DNS record or certificate is needed.

What the proxy must do

  • Route each household address to the member listener, 8787. Never route a public name to the admin listener, 8788: it serves the admin site, the administrator API, the Seerr webhook and /metrics, and has no gate of its own beyond the sign-in.
  • Pass the client's Host unchanged, exactly once, with no port added unless the address has that port. A Host that is no household's address gets 421 unknown_host; a request that does not name exactly one host gets 400 invalid_host. X-Forwarded-Host is never read.
  • Serve household addresses over HTTPS only, and redirect plain http:// at the proxy. Members' passwords and tokens travel in sign-ins and requests.
  • Set X-Forwarded-For (append the client's address, or replace the header with it) and X-Forwarded-Proto: https. Don't pass on a client's own values as if they were yours.
  • Pass WebSocket upgrades (Jellyfin's /socket), for remote control, SyncPlay and live updates.
  • Stream responses and request bodies rather than buffering them, and pass Range requests, for playback and seeking.
  • Leave Cache-Control: no-transform alone. JellyPass compresses its HTML pages itself and marks them no-transform, so a CDN adds no scripts to them. Compression of other responses is optional.

The proxy alone does not make an address a household's: map each address in the admin site under Groups → Addresses, or with PUT /v1/groups/id/addresses on the admin listener. See Household addresses.

Keep Jellyfin's own address, if it has a public one, separate from the household addresses and give it to administrators only. A member who can reach Jellyfin directly bypasses the household checks. List it in JELLYFIN_PUBLIC_URLS so the self-check reports it.

Reaching the admin site

None of the examples publishes the admin listener to the internet. Each publishes it on 127.0.0.1:8788 of the Docker host:

  • On the Docker host: http://127.0.0.1:8788/admin/.
  • From another machine: an SSH tunnel, ssh -L 8788:127.0.0.1:8788 user@docker-host, then the same address.
  • From your LAN: publish it on the host's private address instead, never on a public one. If that address were 192.0.2.10, the line under ports: would be 192.0.2.10:8788:8788.
  • Over HTTPS: a separate proxy host of its own that only your LAN, VPN or an identity-aware gate can reach. The Caddy example has a commented admin.example.com block limited to private addresses, and the Cloudflare Tunnel example one for use only behind Cloudflare Access.

Seerr's webhook goes to the admin listener over the private network, for example http://jellypass:8788/webhooks/seerr, never through a public name.

Client addresses: TRUSTED_PROXIES and Jellyfin's known proxies

Behind a proxy every request reaches JellyPass from the proxy's address. Set TRUSTED_PROXIES to the address (or range) the proxy connects to JellyPass from, so sign-in rate limits apply per client. It is required while the household gateway is on: JellyPass stops at startup without it.

TRUSTED_PROXIES=192.0.2.10

With Docker's published ports this is often the Docker network's gateway address rather than 127.0.0.1; docker network inspect shows it. List only proxies you control: JellyPass walks X-Forwarded-For from right to left, skips trusted proxies and uses the first address it doesn't trust. Requests from addresses not listed are attributed to that address and their header is ignored. TRUSTED_PROXIES never decides which household a request is for.

JellyPass forwards to Jellyfin like any proxy hop. For Jellyfin to see real client addresses, add JellyPass and your reverse proxy in Jellyfin under Dashboard → Networking → Known proxies.

With a CDN in front of your proxy, either have the proxy restore the real client address from the CDN's header, or add the CDN's published ranges to both TRUSTED_PROXIES and Jellyfin's known proxies. Otherwise every client looks like a CDN server. See Chains of proxies and CDNs.

Check it: the deployment self-check

Once the addresses are mapped, sign in to the admin site and choose Run self-check on the Dashboard (or POST /v1/self-check with the admin token). Its proxy result requests each household's address through the proxy, with a one-off challenge, and counts it only if the request arrived with its Host unchanged, a valid X-Forwarded-For, X-Forwarded-Proto matching the address's scheme, and from a peer in TRUSTED_PROXIES.

The request comes from inside JellyPass, so JellyPass must be able to resolve and reach its own public names. The Caddy and Traefik examples give the proxy container those names as network aliases; behind a Cloudflare Tunnel the request goes out to Cloudflare and back.

The check does not prove that the proxy strips forged headers on every path a client could take. When you set the proxy up or change it, also run the checks from outside, from two networks you control.

Examples

Run the commands from a clone of the repository. JellyPass's own settings go in the optional jellypass.env or the setup wizard, and each project needs its own data folder owned by UID 1000.

Caddy

examples/proxy/caddy/ runs JellyPass and Caddy in one Compose project. Caddy gets certificates by DNS-01 through Cloudflare's DNS API, so certificates need no inbound port 80. The stock Caddy image has no DNS providers, so the example builds one with the caddy-dns/cloudflare module.

cd examples/proxy/caddy
cp env.example .env                     # ACME_EMAIL and CLOUDFLARE_API_TOKEN
cp ../../../.env.example jellypass.env  # optional; otherwise the setup wizard
mkdir -m 700 data && sudo chown 1000:1000 data
docker compose up -d --build

The Caddyfile has one site block per household address. Caddy's defaults are what JellyPass needs: don't add header_up Host.

(jellypass_member) {
	reverse_proxy jellypass:8787
}

grove.example.com {
	import jellypass_member
}

heath.example.com {
	import jellypass_member
}
  • DNS token: a Cloudflare API token with Zone → Zone → Read and Zone → DNS → Edit, limited to the zone the household names are in. For another DNS provider, build with its module from caddy-dns and change the acme_dns line.
  • TRUSTED_PROXIES: Caddy's fixed address on the Compose network, 172.30.87.10, which the example sets. If Docker reports the subnet overlaps another network, change the subnet, the address and TRUSTED_PROXIES together.
  • New household: add a site block, add the name to the aliases of the caddy service (for the self-check), point its DNS record at the Docker host, run docker compose up -d, then map it in JellyPass.
  • Cloudflare proxy (orange cloud): keep the household records DNS only with this setup, or use a Cloudflare Tunnel.

Cloudflare Tunnel

examples/proxy/cloudflare-tunnel/ runs JellyPass and cloudflared in one Compose project. Nothing is published to the internet, and Cloudflare terminates HTTPS with its own certificates.

  1. In Cloudflare Zero Trust, choose Networks → Tunnels → Create a tunnel (cloudflared), and copy its token into .env as TUNNEL_TOKEN (cp env.example .env).
  2. Under the tunnel's Public Hostnames, add one per household address: the hostname, service type HTTP, URL jellypass:8787. Leave HTTP Host Header empty.
  3. Run docker compose up -d, then map each address in JellyPass and run the self-check.
  4. Make Cloudflare redirect plain HTTP: a tunnel passes on whatever protocol the visitor used, sign-ins included. Turn on Always Use HTTPS in the zone's SSL/TLS → Edge Certificates, or add a redirect rule for every household hostname.
  5. Check it from outside your network, for each household hostname. It must answer 301 or 308 with Location: https://grove.example.com/web/: 
    curl -sI http://grove.example.com/web/
  • TRUSTED_PROXIES: the cloudflared container's fixed address, 172.30.88.10, alone. No Cloudflare ranges are needed.
  • The admin listener: don't give jellypass:8788 a public hostname unless a Cloudflare Access application covers it and admits your administrators only. Even then, keep Seerr's webhook on the private network.
  • Nothing in front of household hostnames: Cloudflare Access, Under Attack mode or challenge pages stop the Jellyfin apps, the JellyPass app, TVs and the self-check, which cannot answer them.
  • Web Analytics: don't add a Transform Rule that removes no-transform. Keep Network → WebSockets on.
  • Video: streaming goes through Cloudflare's network; check Cloudflare's service terms for your plan before relying on it.

A locally-managed tunnel works as well: the example's config.yml has the same routes.

Nginx Proxy Manager

Create one proxy host per household address, or one host listing several addresses of the same JellyPass (examples/proxy/nginx-proxy-manager/):

  • Details: Domain Names grove.example.com; Scheme http; Forward Hostname / IP jellypass (or the Docker host's address); Forward Port 8787; Websockets Support on; Cache Assets off.
  • SSL: a Let's Encrypt certificate (Use a DNS Challenge if the host isn't reachable on port 80); Force SSL on.
  • Advanced: the snippet below. Don't add a location / here: it replaces NPM's own, and the headers with it.
proxy_buffering off;
proxy_request_buffering off;
proxy_read_timeout 1h;
proxy_send_timeout 1h;

TRUSTED_PROXIES is the address NPM connects to JellyPass from: a fixed address you give NPM on a shared Docker network; or, for NPM on another machine, that machine's LAN address, with JellyPass's 8787 published on a private address only it can reach; or, for NPM on the Docker host using a published port, usually the Docker network's gateway address. For the self-check, add the household names as network aliases of the NPM container, or make sure DNS and hairpin NAT send them back to NPM.

Plain nginx or SWAG

The same proxy as a server block, from the example's nginx.conf. $host has no port: for an address on a port other than 443, use $http_host. Uncomment client_max_body_size in the example if members upload files over 1 MB, and start nginx after JellyPass, or it stops with host not found in upstream "jellypass".

map $http_upgrade $connection_upgrade {
    default upgrade;
    ''      close;
}

server {
    listen 80;
    server_name grove.example.com heath.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    http2 on;
    server_name grove.example.com heath.example.com;

    ssl_certificate     /etc/nginx/certs/fullchain.pem;
    ssl_certificate_key /etc/nginx/certs/privkey.pem;

    location / {
        proxy_pass http://jellypass:8787;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;
        proxy_buffering off;
        proxy_request_buffering off;
        proxy_read_timeout 1h;
        proxy_send_timeout 1h;
    }
}

Traefik

examples/proxy/traefik/ runs JellyPass and Traefik in one Compose project, with certificates by DNS-01 through Cloudflare (CF_DNS_API_TOKEN in .env, the same token as for Caddy). dynamic.yml has one router per household address, all to the member listener:

http:
  routers:
    jellypass-grove:
      rule: Host(`grove.example.com`)
      entryPoints: [websecure]
      service: jellypass-member
      tls:
        certResolver: letsencrypt
  services:
    jellypass-member:
      loadBalancer:
        passHostHeader: true
        servers:
          - url: http://jellypass:8787
  • Docker labels can replace the file: the equivalent labels are commented in the example's compose.yaml. Use one or the other for the same names.
  • Leave out the compress middleware for these routers, and any headers middleware that sets Host or X-Forwarded-Host.
  • TRUSTED_PROXIES: Traefik's fixed address, 172.30.89.10, alone. The household names are network aliases of the Traefik container for the self-check.

Request sizes and timeouts

JellyPass streams uploads on to Jellyfin with no size limit of its own, but a whole request must arrive within 5 minutes. Stock nginx refuses bodies over 1 MB, and Cloudflare limits uploads per plan (100 MB on the Free plan). Stock nginx's 60-second read and send timeouts are short for a stream that pauses while transcoding, which is why the nginx and NPM examples raise them. The full table is in the recipes in the repository.

Common failures

Symptoms and likely causes
SymptomLikely cause
421 {"error":"unknown_host"} on a household addressThe address isn't mapped to a household, or not exactly as the browser sends it (another subdomain, a port). Or the proxy changed Host: NPM's forward host used as Host, cloudflared's HTTP Host Header set, Traefik's passHostHeader: false, Caddy's header_up Host. It is also the answer to any request sent straight to 8787 by IP.
400 {"error":"invalid_host"}The request named more than one host: two Host headers, a Host with a path or user name, or an absolute-form target whose authority is not the Host.
http:// reaches a page instead of redirectingThe proxy or Cloudflare doesn't redirect plain HTTP. Sign-ins over it are unencrypted.
421 for the admin site or the Seerr webhookThey were pointed at 8787; they are on 8788.
JellyPass stops with TRUSTED_PROXIES is requiredThe household gateway is on and TRUSTED_PROXIES is empty.
Self-check proxy warns 0 of NTRUSTED_PROXIES isn't the address the proxy connects from; the proxy doesn't send X-Forwarded-Proto: https; the proxy changes Host; or JellyPass can't reach its own public names (no network aliases, no hairpin NAT, split DNS).
One person's failed sign-ins lock everyone out (429)TRUSTED_PROXIES doesn't name the proxy, so every client counts as the proxy's address.
Jellyfin shows JellyPass's or the proxy's address for every clientJellyfin's Known proxies must list JellyPass and the proxy.
Jellyfin web keeps reconnecting; remote control or SyncPlay failsWebSocket upgrades aren't passed: NPM's Websockets Support off, nginx without the Upgrade and Connection headers, Cloudflare's WebSockets switch off.
Video stalls, or seeking restarts playbackResponse buffering or caching on the proxy, or Range headers stripped.
502 from the proxyThe upstream is wrong (jellypass:8787 from the proxy's network) or JellyPass isn't running.
An analytics script appears in household pagesSomething between JellyPass and the browser removed no-transform from Cache-Control.
